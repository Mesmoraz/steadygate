# Live Demo and Walkthrough Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Pages site that walks through how Steadygate decides and runs the real engine in the browser, with instant precomputed scenarios and live knobs powered by Pyodide.

**Architecture:** A static `site/` folder (HTML/CSS/vanilla JS) plus two Python files: `demo.py`, the bridge from knob state to `gate.evaluate` (it runs both in Pyodide and under CPython for tests), and `build.py`, which runs the real CLI on each example scenario, checks the exit codes and assembles `_site/` with `data/scenarios.json` and the wheel. A Pages workflow builds and deploys `_site/`. The pure JS logic (knobs → results, markdown → HTML) lives in small node-testable modules, the same way `src/steadygate/web/rules.js` does.

**Tech Stack:** Python 3.11+, PyYAML, Pyodide 0.27.7 (jsDelivr), vanilla JS/CSS, GitHub Actions Pages (`actions/upload-pages-artifact@v3`, `actions/deploy-pages@v4`), pytest, and node for the JS tests.

**Spec:** `docs/superpowers/specs/2026-10-25-live-demo-design.md`

**Deviations from the spec, decided while planning:**
- `demo.run` drops the unused `suite` parameter.
- `site/build_scenarios.py` becomes `site/build.py`, because it also assembles the site and copies the wheel.
- Two pure JS modules, `site/knobs.js` and `site/markdown.js`, are added so the logic can be tested in node.
- The build output is `_site/` (git-ignored), not `site/data` + `site/wheels`.

## Global Constraints

- No library changes under `src/steadygate/`. The demo uses only `config.parse`, `gate.evaluate`, `Store`, `report.as_dict`, `report.markdown`, `adapters.load_results` and `models.Result/Status`.
- The only third-party script is Pyodide, from the exact URL `https://cdn.jsdelivr.net/pyodide/v0.27.7/full/pyodide.js`. There are no frameworks, no other CDNs and no build step for JS/CSS.
- Every URL inside the site is relative (`data/scenarios.json`, `wheels/latest.json`, `demo.py`), because Pages serves it under `/steadygate/`.
- Live URL: `https://mesmoraz.github.io/steadygate/`.
- The layout works from 360 px wide. Light and dark themes use CSS custom properties on `:root` with `@media (prefers-color-scheme: dark)`. Every verdict colour comes with its text label.
- Footer copy, exactly: "Runs entirely in your browser. Nothing is sent anywhere."
- Hero headline, exactly: "Your eval passed. Your agent got worse."
- Expected verdicts (the build fails if the CLI disagrees): support/noise 0, support/regression 1, support/broken 2, support/missing 2, trials/noise 0, trials/broken 1.
- Python follows the repo's ruff and mypy settings. Add `"site"` to `[tool.mypy] files`.

## Review Focus

1. **Hostile text in the PR-comment preview.** A case name or error message containing `<script>`, `<img onerror>` or `|` must show as literal text, never as markup. Pinned in Task 3 (`markdown.test`: escaping).
2. **Pyodide or the wheel failing to load** (CDN blocked, offline, old browser). Scenarios must still render and the knobs must show the failure note. Pinned in Task 5, Step 5 (manual check with the CDN blocked).
3. **Knobs that drop or crash every case.** `demo.run` must return the engine's verdict (INCONCLUSIVE), not raise. Pinned in Task 1 (`test_run_with_no_results_is_inconclusive`, `test_crash_every_case_is_inconclusive`).
4. **Float drift from slider steps.** 0.05 steps must produce values like `0.3`, not `0.30000000000000004`, in the results and the report. Pinned in Task 3 (`knobs.test`: rounding).
5. **Absolute URLs breaking under `/steadygate/`.** Pinned in Task 6 (`test_site_uses_relative_urls`).

```json
{"suites": {
  "support": {"label": "Support agent", "config": "<yaml text>", "baselines": [[row, ...] x3],
              "chart": {"metric": "accuracy", "max_regression": 0.05},
              "scenarios": [{"id": "noise", "label": "...", "caption": "...", "expected": 0,
```

  - `class BuildError(Exception)`
  - `build_scenarios(repo: Path, cli: Sequence[str] = (sys.executable, "-m", "steadygate")) -> dict[str, Any]` raises `BuildError` naming every scenario whose exit code differs from `expected`.
  - `assemble(repo: Path, out: Path, wheel: Path | None) -> None` copies each name in `SITE_FILES` from `site/` into `out/`, writes `out/data/scenarios.json`, and, if `wheel` is given, copies it to `out/wheels/` and writes `out/wheels/latest.json` as `{"wheel": "<filename>"}`. The files to copy are the module constant `SITE_FILES` (Task 2: `["demo.py"]`; Tasks 3 and 4 append theirs). A listed file that is missing raises `BuildError`.
  - `main(argv: Sequence[str] | None = None) -> int`: `python site/build.py --out _site [--wheel dist/x.whl]`. Returns 0, or prints `::error::<message>` to stderr and returns 1 on `BuildError`.

### Task 3: Pure JS modules `knobs.js` and `markdown.js`

**Files:**
- Create: `site/knobs.js`, `site/markdown.js`

- Modify: `site/build.py` (append both to `SITE_FILES`)

**Interfaces:**
- Consumes: the scenario rows and suite shape from Task 2.
- Produces (both modules end with `if (typeof module !== "undefined") module.exports = {...}`; in the browser they define globals):
  - `knobsFromResults(suite: "support"|"trials", results: Row[], expectedCases: string[]): Knobs`
    - support: `{cases: {[case]: {accuracy: number, crashed: bool, dropped: bool, latency: number}}, latencyFactor: 1}`. A case is `crashed` if its accuracy row has `status: "error"`. A case in `expectedCases` but missing from `results` is `dropped: true`, with accuracy 0.9 and latency 840 as the values it returns to if un-dropped.
    - trials: `{cases: {[case]: {passes: int}}}` (the count of `value === 1` rows, out of 10).
  - `resultsFromKnobs(suite, knobs: Knobs): Row[]`
    - support: dropped cases emit nothing. Crashed cases emit `{case, metric: "accuracy", value: null, status: "error", message: "LLM judge timed out after 30s"}` plus their latency row. Accuracy is rounded with `Math.round(v * 100) / 100`, and latency is `Math.round(latency * latencyFactor)`.
    - trials: 10 rows per case, `passes` ones first.
  - `runMeans(baselines: Row[][], metric: string): number[]` gives the mean of `ok` rows for that metric in each run.
  - `renderMarkdown(md: string): string` handles exactly what `report.markdown` emits: `### ` heading, pipe tables (with `\|` escapes), `<details><summary>…</summary>` / `</details>`, `<sub>…</sub>`, `- ` lists, and `` `code` ``. It HTML-escapes all text first, then re-allows only those tag shapes.
