Steadygate

Your eval passed. Your agent got worse.

Steadygate is a statistical release gate for LLM evals and flaky tests. It compares each run against your own history, so noise passes, a real drop fails, and a crashed case is never a silent green.

  • ✅ PASS exit 0within normal noise
  • ❌ REGRESSION exit 1worse, not noise
  • ⚠️ INCONCLUSIVE exit 2errored or missing results

How it works

  1. 1 Your eval tool runs

    Keep promptfoo, pytest, JUnit or plain JSONL. Steadygate sits on top of the framework you already use and reads its results file.

  2. 2 An adapter normalises results

    Every result becomes a case · metric · value · status row. A crash or a judge timeout becomes error, not a missing number.

  3. 3 History is the baseline

    Passing runs from main are recorded. Each new run is compared against the median of recent runs, not a fixed number someone guessed once.

How it works, continued

  1. 4 Rules decide

    relative_delta, absolute, mad_outlier and pass_rate check the run. Required rules block the release; optional ones are reported without changing the verdict.

  2. 5 One verdict, one exit code, one PR comment

    PASS, REGRESSION or INCONCLUSIVE, as exit code 0, 1 or 2, so CI can act on it. The same report lands on the pull request as a comment.

Add it to your repo

Run your evals as usual, then hand the results file to the Steadygate action. Runs on main build the history; pull requests get the verdict and a comment.

.github/workflows/steadygate.yml
name: steadygate
on:
  push:
    branches: [main]
  pull_request:

jobs:
  gate:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    steps:
      - uses: actions/checkout@v4
      - run: npx promptfoo eval --repeat 5 --output results.json  # or pytest, Jest, ...
      - uses: Mesmoraz/steadygate@main
        with:
          results: results.json
